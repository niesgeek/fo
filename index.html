01

宣言

世界不缺少工具。 世界需要新的连接方式。

我们生活在一个信息不断增长、智能不断进化的时代。

知识触手可及，创造的门槛正在降低。一个人只要有一个念头，就可能拥有过去只属于机构的资源。

但人与信息、人与工具、人与智能之间，仍然存在一道道边界。

  • I人与信息知道得更多，理解得更少。
  • II人与工具工具越多，人要学的东西也越多。
  • III人与智能它能回答，却还不了解你要去哪里。

我们相信，未来不应该只是拥有更多应用，

而应该让不同的能力彼此理解、协同工作。

因此，我们构想了 FO.CO.FO。 一个以智能为基础、以连接为方式、以人的创造力为中心的数字世界。让复杂的事情变得简单，让曾经遥不可及的想法成为现实。

04

邮箱后端

结论先行： 收件用 Resend，发件走 Amazon SES。

FO.CO.FO 没有自建邮件服务器，也没有用 Google Workspace、Microsoft 365 这类企业邮箱套件。它的 MAIL 产品层是自研的（mail.fo.co.fo 品牌页 + 主站 /mail 应用），但底层投递完全托管：入站由 Resend 的 Forge 接收基础设施接住，再以 Webhook 形式推给应用；出站经 Resend / Amazon SES 发出。以下每一条结论都对应一条可公开复查的 DNS 记录。

Inbound · 收件
Resend

MX 记录 10 receive.forge.rmta.net —— forge.rmta.net 是 Resend 官方的收件域，其文档《Custom Receiving Domains》明确把 receive.forge.rmta.net 列为自定义域名收件时要填写的 MX 值。

+
Outbound · 发件
Amazon SES

SPF 记录 v=spf1 include:amazonses.com ~all —— 域名只授权了 Amazon Simple Email Service 发信。Resend 本身就构建在 SES 之上，收发同源，与 MX 证据互相印证。

收件链路 外部发件人任意邮箱→ Resend Forge 接收receive.forge.rmta.net · AWS 美东→ Webhook 推送Resend → FO.CO.FO 应用→ MAIL 收件箱fo.co.fo/mail
发件链路 MAIL 应用发信用户 @fo.co.fo→ Resend API发信服务层→ Amazon SES 投递amazonses.com · SPF 已授权→ 对方邮箱全球收件方
MX · fo.co.fo 10 receive.forge.rmta.net. 决定性证据。Resend 官方文档原文：收件 MX 可能是 receive.forge.rmta.net、区域变体 receive-euw1.forge.rmta.net，或 inbound-smtp.<region>.amazonaws.com。查看 Resend 文档 ↗
TXT · SPF v=spf1 include:amazonses.com ~all 发件授权只给了 Amazon SES 一家。没有 Google、Microsoft、Zoho、腾讯企业邮等任何其他发件方的 include。
TXT · DMARC _dmarc.fo.co.fo → v=DMARC1; p=reject; sp=reject; pct=100; rua=mailto:dmarc-reports@fo.co.fo; ruf=mailto:dmarc-failures@fo.co.fo; fo=1; 最严格档位：未通过对齐的伪造邮件直接拒收（p=reject），报告回投到自家域名邮箱 —— 说明 @fo.co.fo 邮箱在真实投入使用。
A · 接收服务器 receive.forge.rmta.net → 52.70.1.168 / 98.91.53.166 两个 IP 均属 AWS EC2 美东（us-east-1）地址段，与 Resend 基于 AWS 的基础设施一致。
CNAME · 邮箱站点 mail.fo.co.fo → mail-fo-co-fo.pages.dev MAIL 品牌页托管在 Cloudflare Pages；主站响应头同样为 Server: cloudflare。注意：这只是网页托管，与邮件投递后端无关，别混淆。
NS · 域名解析 ns1.anyns.io / ns2.anyns.io fo.co.fo 的权威 DNS 由 AnyNS 托管；其上级域 co.fo 则是另一套解析（ns1/ns2.cctld.com，且 MX 为 Null MX 不收邮件），两者相互独立。

怎么判断不是其他家？企业邮箱的 MX 都有固定指纹：Google Workspace 是 *.googlemail.com、Microsoft 365 是 *.mail.protection.outlook.com、Zoho、腾讯、阿里也各有专属后缀。fo.co.fo 唯一的 MX 指向 Resend 的 Forge 域，SPF 唯一的 include 指向 Amazon SES —— 证据链闭合。

一句话架构：前端自研（MAIL 应用）＋ 收件 Resend（Forge / rmta.net）＋ 发件 Amazon SES ＋ 站点托管 Cloudflare Pages ＋ DNS 托管 AnyNS。典型的「应用自己做、投递全托管」的现代邮件架构，没有一台自建 SMTP 服务器需要维护。
